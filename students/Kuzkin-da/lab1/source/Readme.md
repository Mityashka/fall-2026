# Лабораторная 1: линейный классификатор на квадратичной функции потерь

В работе на датасете Credit card details решается задача бинарной классификации: по данным клиента нужно предсказать, есть ли у него машина (`Car_Owner`). Линейная модель обучается несколькими вариантами градиентного спуска. Результаты сравниваются между собой и с `RidgeClassifier` из sklearn

## Данные и подготовка

В датасете 1548 строк и 18 столбцов. Классы немного несбалансированы: 924 клиента без машины (N) и 624 с машиной (Y). Столбец `Ind_ID` убран как идентификатор.

Данные делятся на обучающую и тестовую части в пропорции 80/20 с сохранением долей классов (`stratify`, `random_state=32`): 1238 объектов в train и 310 в test. Разбиение выполняется до любой обработки, чтобы информация из теста не попадала в обучение. Все статистики считаются только по train и затем применяются к обеим частям: в `GENDER` пропуски заполняются модой, в `Annual_income` и `Birthday_count` медианой, в `Type_Occupation` значением "Unknown". Категориальные признаки кодируются через `get_dummies`: на train с `drop_first=True`, а test приводится к тем же столбцам (без `drop_first`, чтобы выпадала та же категория, а категории, которых не было в train, игнорировались). В итоге получается 45 признаков. Метки переводятся в {-1, +1}, признаки стандартизируются по среднему и стандартному отклонению обучающей выборки.

## Модель и методы обучения

Модель линейная, предсказание делается по знаку `Xw + b`. Функция потерь квадратичная, `mean((y - Xw - b)^2) / 2`. При нулевых весах ошибка равна 0.5, это точка отсчёта для всех экспериментов.

Сравнивались такие варианты:

- обычный градиентный спуск, шаг 0.01, 1000 эпох;
- SGD с моментумом 0.9, L2-регуляризацией 0.001, батчем 32 и шагом 0.001, 100 эпох, плюс рекуррентная оценка качества `q`;
- наискорейший спуск, где шаг на каждой итерации считается аналитически;
- инициализация весов корреляциями признаков с целевой переменной;
- случайная инициализация и мультистарт из 10 разных seed с выбором лучшего запуска;
- SGD по одному объекту, где порядок обхода задан либо сортировкой по модулю отступа, либо случайной перестановкой.

В наискорейшем спуске оптимальный шаг считается для всего вектора параметров (w, b), а не только для весов. Если направление спуска равно (grad_w, grad_b), то по нему данные проходят как `X @ grad_w + grad_b`, и шаг равен `(|grad_w|^2 + grad_b^2) / mean((X @ grad_w + grad_b)^2)`. Это точный минимум функции потерь вдоль направления антиградиента; формула сверена с численным поиском по прямой и совпала с ним.

## Что получилось по ошибке на обучении

Все методы сошлись практически в одну точку, конечная ошибка везде около 0.382:

| Метод | Начальная ошибка | Конечная ошибка |
|---|---|---|
| Обычный GD | 0.4954 | 0.3824 |
| SGD + Momentum + L2 | 0.4240 | 0.3819 |
| Наискорейший спуск | 0.4183 | 0.3815 |
| Корреляционная инициализация | | 0.3823 |
| Случайная инициализация | 0.5905 | 0.3825 |
| Мультистарт (10 запусков) | | 0.3818 |
| SGD, порядок по отступу | | 0.3837 |
| SGD, случайный порядок | | 0.3832 |

Для SGD с моментумом конечная рекуррентная оценка `q` равна 0.3831. У наискорейшего спуска оптимальный шаг на первых десяти итерациях растёт с 0.353 до 0.421, то есть он заметно больше фиксированных 0.01, и именно поэтому этот метод добирается до минимума быстрее остальных. Функция потерь квадратичная и выпуклая, поэтому от начальных весов результат почти не зависит, а мультистарт и корреляционная инициализация большого выигрыша не дают.

## Качество на тесте

| Модель | Accuracy | Precision | Recall | F1 |
|---|---|---|---|---|
| Steepest GD | 0.7129 | 0.6731 | 0.560 | 0.6114 |
| SGD + Momentum + L2 | 0.7065 | 0.6635 | 0.552 | 0.6026 |
| Correlation init | 0.7065 | 0.6667 | 0.544 | 0.5991 |
| Multistart | 0.7065 | 0.6667 | 0.544 | 0.5991 |
| Random order | 0.6968 | 0.6476 | 0.544 | 0.5913 |
| Margin order | 0.7000 | 0.6633 | 0.520 | 0.5830 |

Лучшим по F1 оказался наискорейший спуск. Но разброс между методами небольшой: по accuracy это около двух процентных пунктов, а тестовая выборка всего 310 объектов, так что говорить о настоящем превосходстве одного метода над другим нельзя. Единственный вывод, который выглядит устойчиво, состоит в том, что порядок обхода по возрастанию отступа (Margin order) оказался самым слабым по recall и F1.

Для лучшей модели матрица ошибок такая: 151 верно угаданный N, 34 ложных срабатывания, 55 пропущенных Y и 70 верно найденных Y. Модель чаще ошибается в сторону "нет машины": из 125 владельцев находит только 70. AUC равен 0.756.

## Отступы

На тесте у наискорейшего спуска минимальный отступ -0.877, максимальный 1.285, средний 0.232. Отрицательных отступов 89 (это и есть ошибки классификации, 89 из 310 даёт те же 71.3% accuracy), положительных 221. Близко к границе лежит заметная часть выборки: 31 объект с модулем отступа меньше 0.1, 71 меньше 0.2 и 201 меньше 0.5. То есть модель уверенно разделяет классы лишь на меньшей части объектов, а признаки несут не очень много информации о наличии машины.

## Сравнение с эталоном

`RidgeClassifier` с `alpha = 0.619` (пересчитан из L2 = 0.001 как `L2 * N / 2`) даёт практически тот же результат, что и собственная реализация:

| Модель | Accuracy | Precision | Recall | F1 |
|---|---|---|---|---|
| Наискорейший спуск (своя реализация) | 0.7129 | 0.6731 | 0.560 | 0.6114 |
| RidgeClassifier | 0.7097 | 0.6699 | 0.552 | 0.6053 |

Разница меньше одного процентного пункта по всем метрикам, что подтверждает корректность ручной реализации градиента, функции потерь и самого спуска.

## Итог

Линейный классификатор на квадратичных потерях достигает на этой задаче примерно 71% accuracy и F1 около 0.61. Выбор метода оптимизации и способа инициализации почти не влияет на итог, потому что задача выпуклая и все методы приходят к одному и тому же решению; отличается лишь скорость сходимости, и здесь выигрывает наискорейший спуск с аналитическим шагом. Совпадение с `RidgeClassifier` говорит, что реализация написана верно. Перенос всей обработки данных после разбиения на train и test почти не изменил метрики (раньше accuracy наискорейшего спуска была 0.716, теперь 0.713), то есть заметной утечки не было, но теперь оценка честная. Дальнейший рост качества стоит искать не в оптимизаторе, а в признаках или в более гибкой модели.
